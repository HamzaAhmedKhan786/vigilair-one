# Hardware-free research demonstration

VigilairOne keeps its operations console, incident review, replay, and Challenge 05 adapters. **Overview** and **Research Lab** read one app-level research workspace backed by the same FastAPI scenario, model registry, virtual sensors and SQLite media/annotations. Overview opens by default. The map uses [MapLibre GL JS](https://maplibre.org/maplibre-gl-js/docs/) with locally generated GeoJSON and a blank offline style by default. Its 28 zones and trajectories are fictional and centered on synthetic coordinates. They do not identify facilities or infer a location from uploaded media.

## Run and inspect

Run `scripts/run_demo.ps1`, then open Overview or Research Lab. The backend exposes `/api/research/scenario`, `/models`, `/models/refresh`, `/sensors`, `/media`, and `/health`. The UI replays one deterministic 31-observation track at a 200 ms screen interval; scenario time advances ten seconds per observation. The predefined acoustic cue, visual review point, and zone transition are **simulated event labels**, not detections or sensor activations. Click an event to seek to its step. The existing experimental YOLO and LIF/SNN fixture remains separately labeled. Switching tabs keeps the fictional site, replay step, play state, selected media, model status and annotations in memory; writes persist through the API.

Overview retains the incident queue, operator decision workflow, camera replay, regional history and incident export. Selecting a fictional sector, or inspecting a track after selecting it, can project the synthetic VIG-042 drone and VIG-038 bird site-local paths inside that sector. This is explicitly an **illustrative projection**, never a geographical association. The camera replay shows its own site-local path graph and original synthetic latitude/longitude metadata. Uploaded recordings are never used to derive a fictional position.

The optional **Live video** toggle uses a browser-playable `VITE_LIVE_CAMERA_URL` when configured and otherwise asks permission for the laptop camera. **Live microphone** asks permission for local audio and shows measured RMS level in dBFS. With a virtual microphone at the selected fictional site, **Capture 5 s WAV** resamples local audio to 16 kHz mono PCM, preserves it through the existing media API and exposes waveform/FFT/log-Mel analysis. Sound activity is not a drone classification. Live feeds are local previews; neither feed is sent to a model automatically. The browser requires HTTPS or localhost and device permission. An optional licensed MapLibre style may be configured with `VITE_RESEARCH_BASEMAP_STYLE_URL`; failed style loading falls back to the blank view. A basemap under fictional coordinates must never be read as the site’s real location.

The map uses a connected flat-top hex grid with shared polygon edges. Four neighboring cells are emphasized initially; the full 28-cell fictional grid remains selectable. The drone icon, past trail, estimated dotted path, nearby watch cells, predicted-next cell, and monitoring/predicted/active/received handoff labels follow the selected replay step. The estimate uses only the current and preceding synthetic positions, except for a clearly seeded first frame. It projects constant velocity for up to 80 scenario seconds and carries no measured confidence or field accuracy. The 2D/3D switch changes pitch and fictional cell extrusion; zoom buttons control the same local MapLibre view. No terrain tiles or physical controls are involved.

The editable grid configuration is `data/research_sites.json`. It must contain 24–35 sites and 3–4 initially visible connected neighbors. The shared geometry and adjacency logic live in `backend/research/hex_grid.py`. Trajectory distance and heading use the existing geospatial functions; the displayed errors compare those results against independently constructed local metric-plane truth. Those errors do not measure physical field accuracy. UI frame timing, WAV feature processing time, and model inference latency are different quantities. Only the first two are measured in this research view.

## Model packages

`models/registry.json` names acoustic CNN + LIF/SNN, RF-DETR Nano, YOLO comparison, and MobileNetV3-Small baseline packages. A complete `models/<package-id>/package.json` is discovered automatically and may override a placeholder. Each artifact path stays inside `models/`, and weights are Git ignored. A package needs a non-placeholder version, exact preprocessing, class order, input and output tensor specifications, training source, dataset version, license, a weight file, and its SHA256. **Refresh** checks paths and hashes without deserializing or executing weights. `package_complete_unverified` means metadata and bytes agree; it is not an inference, accuracy, safety, or benchmark result. Resolve architecture-specific runtime compatibility and run held-out evaluation offline after the teammate provides trusted exports. The existing Challenge 05 adapter is documented in [CHALLENGE05_INTEGRATION.md](CHALLENGE05_INTEGRATION.md). In particular, an arbitrary `.pt` checkpoint must not be executed merely because it has that extension.

The official Challenge 05 train/validation/test split is never rewritten by this module. Keep organizer data and transferred weights outside Git. Record their release, license, digest, class order, preprocessing and calibrated decision threshold before evaluation. The acoustic research branch expects five-second, 16 kHz mono audio transformed to 224×224 log-Mel input when its eventual export contract specifies it. RF-DETR requires a full compatible detector export. Existing YOLO replay stays available as a comparison baseline. Current registry entries intentionally remain incomplete.

## Virtual media and evidence

Create virtual microphones or cameras against fictional sites. Upload WAV, MP3, MP4, WebM, JPEG or PNG (maximum 100 MiB) and select a matching sensor. The server validates media type, stores the original bytes in `artifacts/media`, records SHA256, size and available metadata in local SQLite, and returns the original for playback. Human positive, negative, or uncertain labels occupy a separate table; they do not rewrite media or create model predictions. If `ffprobe` is installed, container metadata is extracted. Browser codec support varies; a valid file may still not play in a given browser. WAV spectral charts require PCM WAV. MP3 and video are playable but have no server spectral chart. The WAV endpoint computes waveform RMS, FFT and a log-Mel matrix from uploaded PCM; these are measured features, not classifications.

The research API has no physical actuator endpoint. Deploy only on localhost or behind an authenticated reverse proxy for trusted teams: the prototype upload and annotation API does not implement user accounts. Keep licensed media, model artifacts, and personal information out of the public repository. The existing operations console and its advisory operator decisions remain separate.

## Verification and remaining dependencies

Run `scripts/verify_project.ps1`, `npm run test:browser`, and `npm run build`. Browser tests use Playwright Chromium or `PLAYWRIGHT_CHANNEL=msedge`. The registry and UI can run with all four model packages missing. Remaining research dependencies are trusted trained exports with their metadata, licensed evaluation media, calibrated thresholds, a held-out split, measured hardware latency and power, and a supported runtime for each export. No current screen claims these results.
